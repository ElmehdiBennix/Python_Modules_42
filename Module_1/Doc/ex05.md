## 3. Concepts

### 3.1 The five filters

| Function | Effect | Operators used | Allowed |
|---|---|---|---|
| `ft_invert` | each channel becomes `255 - channel` | `-` | ✅ `=, +, -, *` |
| `ft_red` | only the red channel survives | `=` | ✅ `=, *` |
| `ft_green` | only the green channel survives | `=` | ✅ `=, -` |
| `ft_blue` | only the blue channel survives | `=` | ✅ `=` |
| `ft_grey` | the three channels are averaged | `=` (plus `np.mean`) | ✅ `=, /` |

All five return an array with **the same shape as the input**, `(H, W, 3)`.

### 3.2 Inverting a colour

For a pixel `(R, G, B)`, the inverted pixel is `(255-R, 255-G, 255-B)`:

```
white (255,255,255)  ->  black   (0,0,0)
black (0,0,0)        ->  white   (255,255,255)
red   (255,0,0)      ->  cyan   (0,255,255)
```

`255` is the **maximum** value of a `uint8` channel, which is why it is the correct
constant. NumPy applies `255 - array` to every element at once — no loop required.

```python
return 255 - array
```

### 3.3 Isolating one channel

```python
arr_copy = array.copy()
arr_copy[:, :, 1] = 0     # kill green
arr_copy[:, :, 2] = 0     # kill blue
return arr_copy
```

* `arr_copy[:, :, 1]` selects **every row, every column, channel 1**.
* `:` means *"all of them"*. `[:, :, i]` is the standard NumPy idiom for *"channel
  `i` of the whole image"*.
* Assigning `0` sets that channel to black.

### 3.4 `.copy()` — avoiding the aliasing trap

```python
arr_copy = array.copy()
```

`arr_copy = array` (without `.copy()`) would not create a second image — it would
create a **second name for the same object**. Setting `arr_copy[:, :, 1] = 0` would
then destroy the original image. `.copy()` allocates a genuinely independent array.

This matters in the test program:

```python
array = ft_load("../subject/landscape.jpg")
ft_invert(array)
ft_red(array)
ft_green(array)
```

All five filters are applied to the **same** `array`. Without `.copy()` inside
`ft_red`, `ft_green` and `ft_blue`, applying `ft_red` would destroy `array` and the
subsequent filters would operate on a black-and-red picture. `.copy()` guarantees
that every filter starts from the pristine original.

> **Verification.** After calling all five filters, the original array is
> byte-for-byte identical to a freshly loaded one.

### 3.5 `uint8` and saturation

`255 - array` on a `uint8` array stays within the range 0–255, so no overflow
occurs. This is different from a **signed** `int8` array, where `255 - 200 = 55` is
fine but `-1` would wrap around to `127`. Keeping the dtype `uint8` avoids the
problem entirely.

### 3.6 Greyscale — averaging the channels

The classic luminance of a pixel is the mean of its three channels:

```
pixel (30, 60, 90)  ->  (30 + 60 + 90) / 3 = 60
```

Two implementation constraints have to be satisfied at once:

* the **shape** of the image must be preserved, so the result must still have three
  channels;
* the **operator restrictions** allow only `=` and `/`.

`np.mean(array, axis=2)` satisfies both: it computes the mean along the channel
axis and uses no operator other than the assignment that stores the result. The
value is then written into all three channels of a copy:

```python
grey = array.copy()
value = np.mean(array, axis=2)
grey[:, :, 0] = value
grey[:, :, 1] = value
grey[:, :, 2] = value
return grey
```

* `np.mean` accumulates in `float64`, so there is no `uint8` overflow, even for
  bright pixels.
* Assigning a float into a `uint8` array truncates towards zero, so the result
  differs from the exact mean by at most one unit out of 255 — the usual
  quantisation of an 8-bit greyscale.
* The output keeps the `uint8` dtype, exactly like the other four filters, which
  makes it display correctly and keeps the five functions consistent.

### 3.7 Displaying the results

```python
plt.figure("Original")
plt.imshow(array)
plt.axis("off")
plt.show()
```

* `plt.figure("Name")` creates a **named figure**. Calling it before each `imshow`
  gives every filter its own window instead of drawing them on top of each other.
* `plt.axis("off")` hides the axes — appropriate here, since ex05 imposes no
  "display the scale" requirement (unlike ex03).
* `cmap="gray"` is needed for `ft_grey`, whose output is a greyscale image.

## 4. Validating the input

Every filter performs the same two checks:

```python
if not isinstance(array, np.ndarray):
    raise TypeError("Input must be a numpy ndarray.")
if array.ndim != 3 or array.shape[2] != 3:
    raise ValueError(
        "Input must be a 3D array with 3 colour channels.")
```

* The first check rejects anything that is not a NumPy array.
* The second check guarantees the **3D RGB** contract. Without it, indexing
  `array[:, :, 1]` on a 2D array raises `IndexError: too many indices for array`,
  and on a 4D array it silently addresses the wrong axis. Both cases are caught
  before any computation happens.

The `except` clauses list `(TypeError, ValueError, IndexError)`. `IndexError` is
included as a safety net for any indexing error that the validation does not
anticipate, which guarantees that **no exception escapes the function** — a
requirement of the subject.

## 5. Implementation walkthrough

`ex05/pimp_image.py`, one function in full:

```python
def ft_red(array: np.ndarray) -> np.ndarray:
    """Keep only the red channel of an image, zeroing out green and blue.

    Args:
        array: A 3D numpy array representing the image pixels.

    Returns:
        A numpy array with only the red channel active.
    """
    try:
        if not isinstance(array, np.ndarray):
            raise TypeError("Input must be a numpy ndarray.")
        if array.ndim != 3 or array.shape[2] != 3:
            raise ValueError(
                "Input must be a 3D array with 3 colour channels.")
        arr_copy = array.copy()
        arr_copy[:, :, 1] = 0
        arr_copy[:, :, 2] = 0
        return arr_copy
    except (TypeError, ValueError, IndexError) as error:
        print(f"Error in ft_red: {error}")
        return np.array([])
```

The structure is identical in all five functions:

1. **Validate** the type and the shape of the input.
2. **Copy** the array, so the caller's image is never modified.
3. **Apply** the filter using only the permitted operators.
4. **Return** the new array, with the same shape as the input.
5. **Catch** anything unexpected, print a readable message, and return an empty
   array.

The type hints use `np.ndarray` (from `import numpy as np`), and every function
carries a Google-style docstring, as the subject requires.

## 8. Key takeaways

1. **A colour filter is array arithmetic.** NumPy applies it to every pixel at
   once.
2. **`255` is the constant for inversion**, because it is the maximum value of a
   `uint8` channel.
3. **`arr[:, :, i]` selects one channel** of the whole image; assigning `0` turns
   it black.
4. **Always `.copy()` before modifying an array** — otherwise the caller's image is
   destroyed (aliasing).
5. **Keep the `uint8` dtype** so the values stay within 0–255.
6. **Greyscale is the mean of R, G and B**, and writing that mean into all three
   channels preserves the shape.
7. **The operator restrictions are part of the specification.** Read them
   carefully: each function must return an array with the **same shape** as its
   input, using only the listed operators.
