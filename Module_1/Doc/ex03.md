## 3. Concepts

### 3.1 Slicing a rectangular region out of a 3D array

This is the central line of the exercise:

```python
cropped = img_array[y_start:y_end, x_start:x_end, 0:1]
```

Read it as **three slices separated by commas**:

| Slice | Selects |
|---|---|
| `y_start:y_end` | the **rows** to keep (vertical range) |
| `x_start:x_end` | the **columns** to keep (horizontal range) |
| `0:1` | the **channels** to keep (channel 0 only → Red) |

The result has shape `(y_end - y_start, x_end - x_start, 1)`.

With `img_y = (100, 500)` and `img_x = (450, 850)`:

```
rows    : 500 - 100 = 400
columns : 850 - 450 = 400
channels: 1
        -> New shape after slicing: (400, 400, 1)
```

A **400 × 400** region is a square, which is what makes the transpose of ex04 a
meaningful rotation.

### 3.2 Why `0:1` rather than `0`?

* `img_array[100:500, 450:850, 0]` → shape `(400, 400)` — the channel dimension is
  removed entirely.
* `img_array[100:500, 450:850, 0:1]` → shape `(400, 400, 1)` — the channel
  dimension remains, with a length of 1.

The subject accepts either: *"(400, 400, 1) or (400, 400)"*. Keeping the channel
dimension is the safer habit, because every later slice keeps the same 3D layout and
the row/column axes can no longer be confused.

### 3.3 `.squeeze()` — removing axes of length 1

```python
plt.imshow(cropped.squeeze(), cmap="gray")
```

`squeeze()` removes every axis whose length is 1:

| Array | `.squeeze()` | Shape |
|---|---|---|
| `(400, 400, 1)` | → | `(400, 400)` |
| `(400, 400, 3)` | → | `(400, 400, 3)` (nothing to remove) |
| `(1, 1, 1)` | → | `()` — a **0-dimensional** array |

> **Pitfall.** `squeeze()` removes *all* qualifying axes, not just the intended one.
> A `(1, 1, 1)` crop collapses to a 0-dimensional array whose `.shape` is `()`, and
> unpacking it raises
> `ValueError: not enough values to unpack (expected 2, got 0)`.
> When only the channel axis should disappear, use `cropped[:, :, 0]` or
> `np.squeeze(cropped, axis=2)` instead. `ft_zoom` avoids the problem entirely: it
> never squeezes before unpacking a shape.

### 3.4 Matplotlib — displaying an image

```python
import matplotlib.pyplot as plt

plt.imshow(cropped.squeeze(), cmap="gray")
plt.show()
```

| Call | Behaviour |
|---|---|
| `plt.imshow(data, ...)` | draws the array as an image |
| `cmap="gray"` | greyscale colour map — required for a 2D or single-channel array |
| `plt.show()` | opens the window and blocks until it is closed |
| `plt.figure("Name")` | creates a **named** figure, so several images can coexist |
| `plt.axis("off")` | hides the axes and their ticks |

**Colour maps.** A 3D array of shape `(H, W, 3)` is understood as RGB
automatically and needs no `cmap`. A 2D array of shape `(H, W)` holds
*intensities*, so Matplotlib must be told how to turn a number into a colour;
`cmap="gray"` maps black to white.

### 3.5 Displaying the scale on the x and y axis

The subject asks for the scale to be visible on the image. `plt.imshow()` draws the
axes **by default**: the X axis is labelled with column numbers (pixels counted
from the left) and the Y axis with row numbers (pixels counted from the top).

`zoom.py` satisfies the requirement simply by **not** calling `plt.axis("off")`.
Calling `plt.axis("off")` would hide the axes and remove the scale.

The scale can also be made explicit:

```python
plt.xlabel("X (pixels)")
plt.ylabel("Y (pixels)")
plt.title("Zoomed region")
```

### 3.6 The `if cropped.size > 0:` guard

```python
if cropped.size > 0:
    plt.imshow(cropped.squeeze(), cmap="gray")
    plt.show()
```

* `cropped.size` is the **total number of elements**, not the number of rows.
* On error the function returns `np.array([])`, an empty array. Calling `imshow` on
  it would either raise or open a blank window; testing `.size > 0` first lets the
  program skip the display.
* This is the *"the program must not stop abruptly"* requirement in practice.

### 3.7 Reading `img_array.shape[:2]`

```python
h, w = img_array.shape[:2]
```

* `img_array.shape` is `(768, 1024, 3)`.
* `shape[:2]` takes the **first two** elements → `(768, 1024)`.
* Unpacking gives `h = 768` (height, i.e. rows) and `w = 1024` (width, i.e.
  columns).

> **The ordering matters.** NumPy is `(height, width)` = `(rows, columns)`, which
> is the opposite of the `(x, y)` convention used by `imshow`. Always name the
> variables explicitly rather than relying on position.

### 3.8 Validating the crop coordinates

```python
if y_start < 0 or x_start < 0:
    raise IndexError("Start coordinates cannot be negative.")
if y_end > h or x_end > w:
    raise IndexError("End coordinates exceed image dimensions.")
if y_start >= y_end or x_start >= x_end:
    raise ValueError("Start must be strictly less than end.")
```

Three rules with three distinct meanings:

* a negative start would index before the beginning of the array;
* an end beyond the image would run off the edge;
* a start greater than or equal to the end describes an empty or reversed range.

`IndexError` is the natural exception for *"that index does not exist"*, and
`ValueError` for *"the combination of values is invalid"*.

### 3.9 Tuple unpacking and `all()` with a generator

```python
if not isinstance(img_x, tuple) or not isinstance(img_y, tuple):
    raise TypeError("img_x and img_y must be tuples.")
if len(img_x) != 2 or len(img_y) != 2:
    raise ValueError("Tuples must contain exactly 2 elements.")

x_start, x_end = img_x
y_start, y_end = img_y

if not all(
    isinstance(v, int) and not isinstance(v, bool)
    for v in (x_start, x_end, y_start, y_end)
):
    raise TypeError("Tuple coordinates must be integers.")
```

* Unpacking `a, b = some_tuple` raises `ValueError` when the tuple has the wrong
  length — but the length is checked first, so a clearer error can be raised
  instead.
* `all(generator)` returns `True` only if the generator yields `True` for **every**
  item. The generator expression tests each coordinate with
  `isinstance(v, int) and not isinstance(v, bool)`.
* `bool` is excluded explicitly because `isinstance(True, int)` is `True`.

## 4. Implementation walkthrough

`ex03/zoom.py`:

```python
def ft_zoom(img_array: np.ndarray, img_x: tuple, img_y: tuple) -> np.ndarray:
    try:
        ...validation...

        h, w = img_array.shape[:2]

        ...range checks...

        cropped = img_array[y_start:y_end, x_start:x_end, 0:1]

        print(f"New shape after slicing: {cropped.shape}")
        print(cropped)

        return cropped

    except (TypeError, ValueError, IndexError) as error:
        print(f"Error in ft_zoom: {error}")
        return np.array([])


def main() -> None:
    """Load image, zoom region, and display the result."""
    img_array = ft_load("../subject/animal.jpeg")
    if img_array is None:
        return

    print(img_array)

    cropped = ft_zoom(img_array, img_x=(450, 850), img_y=(100, 500))

    if cropped.size > 0:
        plt.imshow(cropped.squeeze(), cmap="gray")
        plt.show()
```

* `main()` loads the image, **prints the pixel content of the whole image** — the
  subject's *"The pixel content of the image"* — then zooms, then displays.
* `if img_array is None: return` is the graceful exit when loading failed, so
  `ft_zoom` never receives `None`.
* Printing the full 768 × 1024 × 3 array produces a long output; NumPy abbreviates
  the middle with `...` so it stays readable.

## 7. Key takeaways

1. **`arr[y_start:y_end, x_start:x_end, channel]`** slices a rectangular region out
   of an image. The three slices are *rows*, *columns*, *channels*.
2. **`0:1` keeps the channel axis**, `0` removes it. The subject accepts both.
3. **`.squeeze()` removes every axis of length 1** — and turns `(1, 1, 1)` into a
   0-dimensional array. Use `arr[:, :, 0]` when only the channel axis should go.
4. **`cmap="gray"`** is required for 2D arrays; 3D RGB arrays are understood
   automatically.
5. **Axes are drawn by default.** `plt.axis("off")` hides them, which is precisely
   what the "display the scale" requirement is about.
6. **`.size` counts elements**, not rows. It is the simplest way to check that
   something was actually produced.
7. **NumPy is `(y, x)`** while most image APIs are `(x, y)`. Name the variables
   explicitly and never rely on the order.
