## 3. What is a 2D array?

A 2D array is a **grid**: rows of columns. In pure Python it is a list of lists.

```python
family = [[1.80, 78.4],     # row 0
          [2.15, 102.7],    # row 1
          [2.10, 98.5],     # row 2
          [1.88, 75.2]]     # row 3
```

* 4 rows and 2 columns → the shape is `(4, 2)`.
* `family[0]` is the first row → `[1.80, 78.4]`.
* `family[0][1]` is the second item of the first row → `78.4`.
* NumPy names the two dimensions **rows** and **columns**, and adds a third
  dimension for the colour channels of an image.

### 3.1 Three ways to index a 2D array

```python
family[1]          # whole row 1              -> [2.15, 102.7]
family[1][0]       # item of row 1            -> 2.15
family[1, 0]       # NumPy syntax: row 1, col 0 -> 2.15
```

The comma syntax `arr[row, column]` is specific to NumPy and is the form used for
images in ex03 and ex04.

## 4. Concepts

### 4.1 `.shape` — the dimensions of an array

```python
arr = np.array(family)
print(f"My shape is : {arr.shape}")
```

`shape` is a **tuple** describing the size of each axis:

| Array | `.shape` | Meaning |
|---|---|---|
| `[[1, 2], [3, 4]]` | `(2, 2)` | 2 rows × 2 columns |
| `[[1, 2, 3, 4]]` | `(1, 4)` | 1 row × 4 columns |
| RGB image | `(H, W, 3)` | Height × Width × 3 channels |
| Greyscale image | `(H, W)` | Height × Width |

The subject's expected output contains `My shape is : (4, 2)`, so the exact format
matters: a space before the colon, a space after the comma, and the shape printed
as a tuple.

### 4.2 Slicing — `array[start:end]`

This is the central skill of the exercise.

```python
sliced_arr = arr[start:end]
```

| Syntax | Meaning |
|---|---|
| `arr[2]` | the element at index 2 |
| `arr[2:5]` | indices 2, 3 and 4 — index 5 is **excluded** |
| `arr[:3]` | from the beginning up to index 2 |
| `arr[2:]` | from index 2 to the end |
| `arr[:]` | everything (a copy) |
| `arr[-1]` | the **last** element |
| `arr[-2:]` | the last two elements |
| `arr[1:-2]` | from index 1 up to (but not including) the second-to-last |

**The `end` index is always excluded** — the interval is *half-open*.

The two calls of the test program:

```python
slice_me(family, 0, 2)   # rows 0 and 1          -> shape (2, 2)
slice_me(family, 1, -2)  # row 1 only             -> shape (1, 2)
```

* `family[0:2]` → rows 0 and 1 → `[[1.8, 78.4], [2.15, 102.7]]`
* `family[1:-2]` → starts at row 1, stops two rows before the end → only row 1 →
  `[[2.15, 102.7]]`

> Negative indices count **from the end**: `-1` is the last element, `-2` the one
> before it. A negative `end` therefore means *"stop this many rows before the
> end"*, which is the idiomatic way to remove trailing rows without knowing the
> total number of rows.

### 4.3 Slicing never raises an out-of-range error

```python
arr[0:99]   # on a 4-row array -> returns all 4 rows, no error
arr[2:1]     # start after end  -> returns an empty array
```

Python slicing is forgiving. Validation therefore focuses on the *types* of `start`
and `end` and on the *structure* of `family`, not on range-checking the indices.

### 4.4 `.tolist()` — back to plain Python

```python
return sliced_arr.tolist()
```

`np.array(...)` produces a NumPy array; `.tolist()` converts it back into nested
Python lists. The prototype asks for a `list`, and the expected output shows Python
list syntax, so `.tolist()` is the correct call. Returning the raw array would
print `array([[1.8 , 78.4 ], ...])` instead.

### 4.5 Ragged (non-rectangular) lists

A 2D array must be **rectangular**: every row must have the same length.

```python
[[1, 2], [3]]     # ragged -> NumPy raises ValueError
```

Modern NumPy (1.24+) refuses to build such an array at all. The implementation
therefore checks the row lengths manually, before calling `np.array`, and raises a
clear `ValueError("All rows must have the same size.")`. This is what satisfies the
*"handle error cases if the lists are not the same size"* requirement.

### 4.6 `enumerate()` — index and value

```python
for idx, row in enumerate(family):
    if not isinstance(row, list):
        raise TypeError(f"Element at index {idx} must be a list.")
```

`enumerate` yields `(index, value)` pairs, which makes it possible to report
**which** row is invalid. The `f"..."` is an **f-string**: the text inside `{}` is
replaced by the value of the variable of that name.

### 4.7 Verifying that every row has the same length

```python
row_len = None
for idx, row in enumerate(family):
    if not isinstance(row, list):
        raise TypeError(f"Element at index {idx} must be a list.")
    if row_len is None:
        row_len = len(row)          # the first row defines the reference length
    elif len(row) != row_len:
        raise ValueError("All rows must have the same size.")
```

* `None` means "not set yet". `row_len` starts as `None` because the length is
  unknown until the first row is examined.
* The `elif` compares every subsequent row against that reference length.
* Calling `len(row)` on a non-list would raise a `TypeError` from Python itself;
  checking `isinstance(row, list)` first produces a clearer message.

## 5. Implementation walkthrough

`ex01/array2D.py`:

```python
try:
    if not isinstance(family, list):
        raise TypeError("family must be a list.")

    if not isinstance(start, int) or isinstance(start, bool):
        raise TypeError("start must be an integer.")

    if not isinstance(end, int) or isinstance(end, bool):
        raise TypeError("end must be an integer.")

    if len(family) == 0:
        raise ValueError("family list cannot be empty.")

    row_len = None
    for idx, row in enumerate(family):
        if not isinstance(row, list):
            raise TypeError(f"Element at index {idx} must be a list.")
        if row_len is None:
            row_len = len(row)
        elif len(row) != row_len:
            raise ValueError("All rows must have the same size.")

    arr = np.array(family)
    print(f"My shape is : {arr.shape}")

    sliced_arr = arr[start:end]
    print(f"My new shape is : {sliced_arr.shape}")

    return sliced_arr.tolist()

except (TypeError, ValueError) as error:
    print(f"Error in slice_me: {error}")
    return []
```

The flow is: **validate the arguments → validate the structure → convert to NumPy →
print the original shape → slice → print the new shape → return as a plain list.**

The order of the two `print` calls matters: the expected output shows the original
shape first, then the new shape, then the sliced data.

## 8. Key takeaways

1. **Slicing is `array[start:end]`**, and `end` is **excluded**.
2. **Negative indices count from the end** — `arr[1:-2]` is the idiomatic way to
   drop trailing rows.
3. **`.shape` is a tuple**: `(rows, columns)` for a table, `(height, width, channels)`
   for a colour image.
4. **Slicing never crashes on a bad range**, so the validation targets types and
   structure rather than indices.
5. **A 2D array must be rectangular** — check the row lengths before handing the
   data to NumPy.
6. **`.tolist()`** converts a NumPy array back into plain Python lists, matching the
   `-> list` prototypes.
7. **`enumerate()`** provides the index *and* the value, which makes error messages
   precise.
