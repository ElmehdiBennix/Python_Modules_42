## 3. The BMI formula

BMI is **weight divided by height squared**, with height in metres and weight in
kilograms:

```
BMI = weight / (height ** 2)
```

| height (m) | weight (kg) | height² | BMI |
|---|---|---|---|
| 2.71 | 165.3 | 7.3441 | 22.5078… |
| 1.15 | 38.4 | 1.3225 | 29.0359… |

`apply_limit(bmi, 26)` then compares each value against `26`:
`22.5 > 26` → `False`, `29.0 > 26` → `True`, giving `[False, True]`.

## 4. Concepts

### 4.1 Type hints (PEP 484 and PEP 604)

```python
def give_bmi(height: list[int | float], weight: list[int | float]) -> list[int | float]:
```

* `list[int | float]` describes "a list whose items are either `int` or `float`".
* The `|` union syntax (**PEP 604**) requires **Python 3.10+**. The module pins
  Python 3.10 in `.python-version`.
* The annotation after `->` describes the return value.
* **Type hints are not enforced at runtime.** They are documentation for readers and
  for static type checkers such as `mypy`. Runtime validation still requires
  `isinstance` checks.

### 4.2 `isinstance()` — runtime type checking

```python
if not isinstance(height, list) or not isinstance(weight, list):
    raise TypeError("Both height and weight must be list types.")
```

`isinstance(obj, Type)` returns `True` when `obj` is an instance of `Type` **or of
any of its subclasses**. The stricter `type(obj) is Type` accepts no subclass at all.

### 4.3 The `bool` subclass of `int`

In Python, `bool` is a subclass of `int`:

```python
isinstance(True, int)   # -> True
```

A check of `isinstance(value, (int, float))` therefore also accepts `True` and
`False`. The implementation excludes them explicitly:

```python
if not isinstance(h, (int, float)) or isinstance(h, bool):
    raise TypeError("Height elements must be int or float.")
```

The expression reads "it is a number **and** it is not a boolean". The same guard
applies to every element of `bmi` and to the `limit` argument.

### 4.4 The builtin exception types in use

| Exception | Meaning | Raised for |
|---|---|---|
| `TypeError` | Wrong **type** of object | a list was expected, a `str` was given; an element is not a number |
| `ValueError` | Right type, invalid **content** | lists of different sizes; empty list; height or weight ≤ 0 |
| `IndexError` | Index out of range | used in ex03 and ex04 for crop coordinates |

### 4.5 `try` / `except` and raising

```python
try:
    ...
    raise TypeError("Both height and weight must be list types.")
    ...
except (TypeError, ValueError) as error:
    print(f"Error in give_bmi: {error}")
    return []
```

* `raise` throws an exception and aborts the current function immediately.
* `except (A, B) as error:` catches several exception types in a single block.
* `error` is the exception instance; `str(error)` yields its message.
* The subject is explicit: *"Any exception not caught will invalidate the
  exercises."* Catching broadly and printing a readable message is the expected
  behaviour.

### 4.6 `zip()` — pairing two sequences

```python
for h, w in zip(height, weight):
```

`zip` walks two iterables in parallel and stops at the shorter one. Because the
lengths are validated beforehand, the loop visits every pair.

### 4.7 NumPy: array creation, vectorised arithmetic, `.tolist()`

```python
h_arr = np.array(height, dtype=float)
w_arr = np.array(weight, dtype=float)

bmi_results = w_arr / (h_arr**2)
return bmi_results.tolist()
```

* `np.array([...], dtype=float)` builds an array of 64-bit floats.
* `**` is the power operator: `h_arr ** 2` squares every element at once.
* `/` is element-wise as well: each weight is divided by the matching squared
  height. This is **vectorisation** — the loop runs in NumPy's compiled code
  instead of in Python.
* `.tolist()` converts the array back into a plain Python `list` of Python `float`
  objects. This matters because the prototype asks for a `list`, and the tester
  prints `type(bmi)` → `<class 'list'>`.

### 4.8 NumPy comparisons produce boolean arrays

```python
bmi_arr = np.array(bmi, dtype=float)
limit_results = bmi_arr > limit
return limit_results.tolist()
```

`bmi_arr > limit` evaluates the comparison for every element and yields an array of
booleans, for example `array([False, True])`. `.tolist()` converts it into
`[False, True]` built from real Python `bool` objects.

### 4.9 `main()` and the `__name__` guard

```python
def main() -> None:
    height = [2.71, 1.15]
    weight = [165.3, 38.4]

    bmi = give_bmi(height, weight)
    print(bmi, type(bmi))
    print(apply_limit(bmi, 26))


if __name__ == "__main__":
    main()
```

* `__name__` equals `"__main__"` only when the file is executed directly
  (`python tester.py`). When the file is imported, `__name__` is the module name.
* The guard therefore means *"run this only on direct execution, not on import"* —
  the standard pattern required by the subject.
* `-> None` indicates that the function returns nothing.

### 4.10 Docstrings (`__doc__`)

```python
def apply_limit(bmi: list[int | float], limit: int) -> list[bool]:
    """Check which BMI values strictly exceed a specified threshold limit.

    Args:
        bmi: List of BMI values (ints or floats).
        limit: Integer threshold to compare against.

    Returns:
        A list of booleans where True means the BMI exceeds the limit.
    """
```

* The docstring is stored on the function object and read back with
  `apply_limit.__doc__`.
* The subject requires one for every function: *"All your functions must have a
  documentation (`__doc__`)"*.
* The `Args:` / `Returns:` layout is the **Google style** convention.
* Docstrings are executable content — they are the first thing a peer reviewer
  reads.

## 5. Implementation walkthrough

`ex00/give_bmi.py`:

```python
try:
    if not isinstance(height, list) or not isinstance(weight, list):
        raise TypeError("Both height and weight must be list types.")

    if len(height) != len(weight):
        raise ValueError(
            "Height and weight lists must have the same size.")

    if len(height) == 0:
        raise ValueError("Lists cannot be empty.")

    for h, w in zip(height, weight):
        if not isinstance(h, (int, float)) or isinstance(h, bool):
            raise TypeError("Height elements must be int or float.")
        if not isinstance(w, (int, float)) or isinstance(w, bool):
            raise TypeError("Weight elements must be int or float.")
        if h <= 0 or w <= 0:
            raise ValueError(
                "Height and weight must be greater than zero.")

    h_arr = np.array(height, dtype=float)
    w_arr = np.array(weight, dtype=float)

    bmi_results = w_arr / (h_arr**2)
    return bmi_results.tolist()

except (TypeError, ValueError) as error:
    print(f"Error in give_bmi: {error}")
    return []
```

The structure is a **validate, then compute** pipeline:

1. **Validate the containers** — both arguments must be lists.
2. **Validate the sizes** — same length, and not empty.
3. **Validate the items** — each one a real number (not a boolean) and strictly
   positive, so the division can never divide by zero.
4. **Compute** — vectorised NumPy arithmetic.
5. **Convert back** — `.tolist()` so the return value is a plain Python list.
6. **Catch anything unexpected** — print a readable message and return `[]` instead
   of crashing.

The positivity check is what makes a division-by-zero impossible. NumPy would
otherwise emit a `RuntimeWarning` and produce `inf` or `nan` rather than raising,
which is why an explicit validation is preferable to relying on an exception.

`ex00/apply_limit` follows the same pattern: type-check the list, type-check the
limit (excluding `bool`), type-check every element, then compare and convert.

## 8. Key takeaways

1. **Validate, then compute.** Checking types and sizes before doing any
   arithmetic keeps invalid input from producing a crash.
2. **`raise` reports a problem; `try`/`except` handles it.** The subject forbids
   letting exceptions escape.
3. **NumPy vectorises.** `w_arr / (h_arr ** 2)` replaces a `for` loop with one
   expression.
4. **`.tolist()` bridges NumPy and plain Python.** The prototypes all ask for a
   `list`, not an `ndarray`.
5. **`bool` is a subclass of `int`** — exclude it explicitly wherever "a real
   number" is meant.
6. **Type hints do not validate anything at runtime.** `isinstance` does.
7. **Every function needs a docstring** describing its parameters and its return
   value.
