# Exercice 00 — Give my BMI

## The problem

`give_bmi` receives two lists of integers or floats, one of heights in metres and
one of weights in kilograms, and returns a list of BMI values. `apply_limit`
receives a BMI list and an integer limit and returns a list of booleans, true only
when the value is strictly above the limit. Both functions reject arguments that
are not lists, lists of different lengths, elements that are not numbers, and
non-positive measurements. The tester uses heights `[2.71, 1.15]` and weights
`[165.3, 38.4]`, which produce
`[22.507863455018317, 29.0359168241966]` and then `[False, True]`.

## The concept

BMI is weight divided by the square of height, so each pair is computed as
`w / h ** 2`. A Python list does not define arithmetic: writing `weight / height ** 2`
raises `TypeError: unsupported operand type(s) for ** or pow(): 'list' and 'int'`.
The list holds pointers to separate float objects, and `**` has no rule for walking
two of those structures in parallel. The manual alternative is
`[w / h ** 2 for h, w in zip(height, weight)]`, which works but executes Python
bytecode and allocates a new float object for every pair.

NumPy removes the per-element objects. `np.array(height, dtype=float)` reads the
list once, allocates one contiguous buffer and stores each value as eight bytes.
The resulting array has shape `(n,)` and dtype `float64`; `dtype=float` is the
request for the default float width, not a request for a Python float. The
expression `w / h ** 2` then creates temporary arrays and runs two compiled loops:

```python
h = np.array(height, dtype=float)
w = np.array(weight, dtype=float)
bmi = w / h ** 2          # shape (n,), dtype float64
return bmi.tolist()       # list of Python floats
```

The cost model is per array, not per element. On one million values, the NumPy
division takes about 0.004 s and the `zip` loop about 0.09 s. On two values the
NumPy call takes about 0.8 µs and the loop about 0.3 µs, because the fixed call
overhead dominates. The loop is also the memory-costlier form at scale: a Python
float object occupies 24 bytes, while a `float64` slot occupies eight bytes, and
each loop result is a newly allocated object.

`.tolist()` is not cosmetic. Without it the function returns an `ndarray`, so the
tester prints `[22.50786346 29.03591682] <class 'numpy.ndarray'>` instead of
the promised `list`. With it, the outer type is `list` and every element is a plain
`float`. The prototype names `list[int | float]` and the conversion is what makes
that name true.

`apply_limit` follows the same path: `bmi_arr > limit` produces a boolean array,
and `.tolist()` turns each `numpy.bool_` into a Python `bool`. The comparison is
strict, so a BMI equal to the limit is false. A threshold written as `>=` would
change the contract without changing any type.

Broadcasting explains both the convenience and the danger. Arrays of shape `(n,)`
and `(n,)` combine element by element. If the lengths differ, NumPy raises
`ValueError: operands could not be broadcast together`; the explicit length check
turns that into a readable message. A stray axis can instead
succeed silently: `(3, 1) + (1, 4)` broadcasts to `(3, 4)`, and a mistaken
`(n, 1)` against `(1, n)` would produce an `n × n` table rather than an error.
Check `.shape` whenever the ranks differ.

Validation has one Python-specific trap. `bool` is a subclass of `int`, so
`isinstance(True, (int, float))` is true and a boolean would pass a naive numeric
check. The code excludes booleans explicitly. Type hints describe intent but are
not enforced at runtime, so every rejected case needs an actual test.

## How to check

Run the tester from `ex00`. The two lines below are the whole expected output, and
the second line is a list of real booleans, not an array:

```bash
cd Module_1/ex00
../.venv/bin/python tester.py
../.venv/bin/python -c "from give_bmi import give_bmi as g; \
print(g([1.8], [70, 80]))"
cd .. && make lint
```

The tester prints `[22.507863455018317, 29.0359168241966] <class 'list'>` followed by
`[False, True]`. The mismatch call prints
`Error in give_bmi: Height and weight lists must have the same size.` and then `[]`,
never a traceback. `make lint` from the module root exits 0 and prints no
diagnostics; `.venv/bin/flake8 ex00` from the same directory is the per-exercise
form.

## Key take away

Validation belongs before computation, because a rejected input is easier to
explain than a broadcast result of the wrong shape. Vectorised expressions replace
loops but keep element-by-element meaning, and their fixed overhead only pays off
as the array grows. Convert back to the type named in the prototype, exclude
booleans from numeric checks, and express a strict threshold with `>` alone.
