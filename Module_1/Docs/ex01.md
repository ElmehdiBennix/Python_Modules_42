# Exercice 01 — 2D array

## The problem

`slice_me` takes a two-dimensional list, a start index and an end index. It prints
the shape of the original array, returns the rows between `start` and `end`, and
prints the shape of the result. The subject requires the slicing method rather
than a manual loop, and it fixes the wording of both lines. Invalid input includes
arguments that are not lists, rows of different lengths, and non-integer indices;
each must be reported instead of crashing. The tester calls the function twice,
first with `(0, 2)` and then with `(1, -2)`.

## The concept

A list of lists is a tree of objects: the outer list holds pointers to row lists,
and each row holds pointers to float objects. `np.array(family)` walks that tree
once and copies the numbers into one contiguous buffer. For the tester's four rows
of two floats, the result has shape `(4, 2)`, dtype `float64` and strides `(16, 8)`.
The address of cell `(i, j)` is `base + i*16 + j*8`. Indexing no longer follows a
pointer to a row and then a pointer to a value; it multiplies and adds.

Shape is `(rows, columns)`, in that order. `len(arr)` returns the first dimension,
the number of rows, because `len` asks only about the outermost sequence. The old
way to recover the column count was `len(arr[0])`; `arr.shape[1]` states it
directly and does not fail on an empty array. Confusing the two produces code that
works until the row count and column count differ.

`family[start:end]` slices axis 0, so it selects rows. The interval is half-open:
`arr[0:2]` keeps rows 0 and 1, and `arr[1:-2]` starts at row 1 and stops two rows
before the end. With four rows the latter returns only row 1, shape `(1, 2)`.
Negative indices count from the back; out-of-range bounds are clipped rather than
rejected, so `arr[1:99]` returns the remaining rows and `arr[99:]` returns shape
`(0, 2)` instead of raising. Code that assumes exactly `end - start` rows therefore
fails at the edges.

The slice is a view, not a copy of the selected rows. Its shape becomes `(2, 2)`
for `arr[0:2]`, but its strides remain `(16, 8)` and its data pointer moves forward
by one row only when `start` is non-zero. The buffer is shared:

```python
arr = np.array(family)               # shape (4, 2), dtype float64
print(f"My shape is : {arr.shape}")
sliced = arr[start:end]              # rows only, still a view
print(f"My new shape is : {sliced.shape}")
return sliced.tolist()
```

Writing to `sliced[0, 0]` writes to `arr[start, 0]`. The `(4, 2) → (2, 2)` change is
therefore a stride-preserving window: the row stride stays 16 bytes, and only the
shape and offset change. `.copy()` is what allocates an independent buffer.
Slicing does not require the result to be contiguous either: `arr[:, 0]` selects
one column with stride 16 and no longer has adjacent elements in memory.

NumPy refuses a ragged nested list in this version with
`ValueError: setting an array element with a sequence`. The code checks every row
length before conversion and raises a clear `ValueError`, because a rectangular
buffer cannot represent rows of different lengths. The check also catches a row
that is not a list at all, which would otherwise fail during conversion with a
less specific message.

`.tolist()` reverses the construction for the return value: it produces a list of
lists of Python floats. That restores the type promised by the prototype, but it
also discards the array metadata. Printing the shape before the conversion is what
preserves the information the caller cannot recover from the nested list.

## How to check

Run the tester from `ex01` and expect four shape lines and two sliced lists, in the
order shown here:

```bash
cd Module_1/ex01
../.venv/bin/python tester.py
../.venv/bin/python -c "from array2D import slice_me as s; \
print(s([[1, 2], [3]], 0, 1))"
cd .. && make lint
```

The tester prints `My shape is : (4, 2)`, `My new shape is : (2, 2)`, then
`[[1.8, 78.4], [2.15, 102.7]]`; it repeats `My shape is : (4, 2)`, prints
`My new shape is : (1, 2)`, then `[[2.15, 102.7]]`. The ragged call prints
`Error in slice_me: All rows must have the same size.` followed by `[]`. `make lint`
from the module root exits 0 with no diagnostics; `.venv/bin/flake8 ex01` is the
per-exercise form.

## Key take away

Shape is metadata, and a row slice changes the row count while preserving the row
stride. The half-open interval explains every bound, including negative and
out-of-range values. Rectangularity is a precondition for a 2D array, so check it
before conversion. A slice is a view over shared memory; copy explicitly when the
caller must keep the original. `.tolist()` restores the promised Python type, and
the fixed output wording includes the spaces around the colons.
