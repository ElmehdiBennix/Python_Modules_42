# Exercice 05 — Pimp my image

## The problem

`pimp_image.py` provides five filters: `ft_invert`, `ft_red`, `ft_green`,
`ft_blue` and `ft_grey`. Each receives an RGB array and returns a filtered array
of exactly the same shape. The subject restricts the operators per function:
inversion may use `=`, `+`, `-` and `*`; red may use `=` and `*`; green may use
`=` and `-`; blue may use only `=`; grey may use `=` and `/`. The tester loads
`landscape.jpg`, displays the six images and prints the docstrings.

## The concept

A colour image is a `uint8` array of shape `(height, width, 3)`. Channel selection
uses `arr[:, :, i]`: the two colons mean every row and column. The result is a
two-dimensional view over the original buffer, not a copy.

Inversion subtracts each pixel from 255, the maximum channel value:

```python
return 255 - array
```

The result keeps dtype `uint8`, and every value stays in range: 0 becomes 255, 255
becomes 0. The order matters. `255 - array` is safe, but `array - 255` wraps:
substituting 0 gives 1, because `uint8` is modular and the negative result is stored
modulo 256. The same rule turns 200 + 100 into 44; there is no overflow exception
and no saturation.

Widening before arithmetic is the general fix. `array.astype(np.int16) + 100`
produces 300, and `np.clip(..., 0, 255).astype(np.uint8)` brings it back to 255.
Clipping after the wrap cannot recover the original value: 44 is already a legal
`uint8`. The computation must happen in a dtype wide enough to hold the result.

The three colour filters keep one channel and zero the other two. This is the
actual code for red:

```python
arr_copy = array.copy()
arr_copy[:, :, 1] = 0
arr_copy[:, :, 2] = 0
return arr_copy
```

The channel assignment uses only `=`, so it fits the red set `=, *`, the green set
`=, -` and the blue set `=`. The restriction is on the shape of the expression, not
on correctness: `array * 0` would also be legal for red but would produce a black
image, and `255 - array` would be correct for inversion but illegal for red. A
filter can use a permitted operator and still be wrong; the operator list only
bounds the syntax.

`array.copy()` is required. A plain assignment `arr_copy = array` aliases the
buffer, so `arr_copy[:, :, 1] = 0` would zero the caller's channel; the tester
applies all five filters to one loaded array, so one destructive filter corrupts
every later result. `np.shares_memory(array, array.copy())` is false.

Greyscale is the mean of the three channels. `np.mean(array, axis=2)` reduces the
channel axis and returns shape `(height, width)` in `float64`. Writing that value
into all three channels of a copy restores the original shape. The assignment casts
back to `uint8` by truncation: a mean of 10.333 becomes 10, not 11. Rounding would
need an explicit `np.round` before assignment.

The grey set is `=, /`. A hand-written `(r + g + b) / 3` uses `+`, which is not
permitted, so `np.mean` keeps the source within the rule; the restriction covers
operators written in the function, not library internals. Returning `np.mean(...)`
directly would change the shape, so the value is assigned into three channels.

Every function validates a three-dimensional, three-channel ndarray; a greyscale or
RGBA input is rejected with a message rather than failing inside a slice. In-place
`array += 1` is another failure mode: it mutates the caller's buffer and wraps at
256.

## How to check

Run the tester from `ex05` and expect the image shape, six Agg warnings and the
five docstrings. Run the small shape check to confirm that a filter preserves the
shape.

```bash
cd Module_1/ex05
MPLBACKEND=Agg timeout 30 ../.venv/bin/python tester.py
../.venv/bin/python -c "import numpy as np; \
from pimp_image import ft_grey; \
print(ft_grey(np.zeros((2, 2, 3), np.uint8)).shape)"
cd .. && make lint
```

The tester prints `The shape of image is: (257, 450, 3)`, then
`--- Function Docstrings ---` and the five docstrings. Each `plt.show()` emits
`UserWarning: FigureCanvasAgg is non-interactive`; the warning is expected on the
headless backend. The small check prints `(2, 2, 3)`. The colour filters zero the
other channels with `= 0`, not by multiplying by a mask. `make lint` from the
module root exits 0 with no diagnostics; `.venv/bin/flake8 ex05` is the
per-exercise form.

## Key take away

Colour filters are array arithmetic applied to every pixel at once, and shape and
dtype are part of the contract. One channel is an axis selected with `[:, :, i]`,
not a separate image. Copy before mutating, because assignment aliases the buffer.
`uint8` wraps silently, so widen or clamp before arithmetic that can leave 0 to
255, and remember that `255 - px` is safe while `px - 255` is not. The permitted
operators constrain the expression, not its correctness.
