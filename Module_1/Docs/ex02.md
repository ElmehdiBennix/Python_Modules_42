# Exercice 02 — Load my image

## The problem

`ft_load` receives a path, loads the image, prints its shape and returns the pixel
data as an array. The subject requires at least JPG and JPEG support, and any
failure must produce a clear message rather than a traceback. The tester calls
`ft_load("../subject/landscape.jpg")` and prints the returned value, so the output
is the shape line followed by the array. A wrong path, a non-string argument, an
unsupported extension or a corrupt file each exercise a different error branch.

## The concept

A JPEG is a compressed stream. The file on disk is 22,793 bytes, while the decoded
pixels occupy 346,950 bytes, because the header describes a 257 by 450 image with
three `uint8` channels and the decoder reconstructs all of them. File size therefore
says nothing about array size or shape. The shape comes from the image header and
the decode step, and `array.nbytes` reports the buffer size after decoding.

Pillow represents the file as an `Image` object with a mode and a size. For this
JPEG the mode is `RGB` and the size is `(450, 257)`, width first. `np.array` converts
that object to an `ndarray` with shape `(257, 450, 3)`, dtype `uint8` and strides
`(1350, 3, 1)`. The axis order is height, width, channel: pixel `(y, x)` is
`arr[y, x]`, and its address is `base + y*1350 + x*3`. The channel order is red,
green, blue, which matches what `imshow` expects; it is not BGR.

The conversion copies the pixels:

```python
with Image.open(image_path) as img:
    img_array = np.array(img.convert("RGB"))
```

The returned array owns its data (`owndata` is true), and editing it does not
change the PIL image. `.convert("RGB")` is what makes the shape predictable. A
greyscale JPEG opens in mode `L` and would produce `(H, W)`, so any later access to
`shape[2]` fails. An image with transparency opens in mode `RGBA` and produces
`(H, W, 4)`, so later code that assumes three channels reads the wrong axis or
passes four channels to a three-channel operation. Converting at the boundary turns
both cases into `(H, W, 3)`.

`print` on the array does not show every pixel. NumPy's display threshold defaults
to 1000 elements, and this array has 346,950, so the repr prints the first and last
rows of each corner block and inserts `...` between them. The ellipsis is a display
decision, not a truncated array; the buffer still contains every pixel. The repr
also shows the nesting: `[[[19 42 83] ...]]` is one pixel triple inside the first
row inside the image.

The error paths are part of the same boundary. The argument is checked as a string
before `Path` is constructed, so an integer path produces a `TypeError` message
rather than a `Path` failure. The suffix is lower-cased before comparison, so
`.JPG` and `.JPEG` are accepted. A missing file is checked before opening, and
`UnidentifiedImageError` covers a file with a valid extension but invalid content.
The function returns `None` on every failure. Callers must test `is None`:
`bool(np.array([1, 2]))` raises `ValueError`, because an array with more than one
element has no unambiguous truth value, so `if not ft_load(path)` is a trap.

## How to check

Run the tester from `ex02`. The shape line comes first, then the abbreviated array
with `...` in place of the omitted rows and columns. The missing-file call must
return `None` after one readable line.

```bash
cd Module_1/ex02
../.venv/bin/python tester.py
../.venv/bin/python -c "from load_image import ft_load as f; \
print(f('missing.jpg'))"
cd .. && make lint
```

The tester prints `The shape of image is: (257, 450, 3)` and then the array, whose
first pixel is `[19 42 83]` and whose final pixels are `[1 1 1]`. The missing-file
call prints `Error in ft_load: File not found: missing.jpg` and then `None`.
`make lint` from the module root exits 0 and prints no diagnostics;
`.venv/bin/flake8 ex02` is the per-exercise form.

## Key take away

An image is an array with a channel axis, and its axis order is height, width,
channel, not the x/y order used by plotting libraries. Normalise the colour model
at the boundary so the rest of the program sees one shape. `np.array` copies the
decoded pixels, so the array and the PIL object are independent. The printed
ellipsis is a display threshold, not missing data. Return a sentinel on failure and
test it with `is None`, because a multi-element array cannot be used as a boolean.
