# Exercice 04 — Rotate me

## The problem

`rotate.py` loads `animal.jpeg`, cuts a square region out of it, transposes that
region and displays the result. It must print the new shape and the data of the
image after the transpose. The subject forbids `.T` and `transpose()` here: the
algorithm must be written by hand. The crop is 400 by 400, so the transposed
result is also 400 by 400. The subject's sample output starts from the cropped
shape and shows the transposed pixels. This program prints the loaded shape
`(768, 1024, 3)` and the original pixels, then prints
`New shape after Transpose: (400, 400)` and the transposed pixel data; it does
not print the cropped shape.

## The concept

A transpose permutes axes. The element at row `i` and column `j` moves to row `j`
and column `i`, the shape changes from `(rows, columns)` to `(columns, rows)`, and
the strides swap from `(row_stride, column_stride)` to
`(column_stride, row_stride)`. On a 2D array, `.T` performs exactly that metadata
change and copies nothing: the result shares the buffer, and writing through the
transpose writes to the original. On a 3D image, `.T` reverses all three axes, so it
would turn `(H, W, C)` into `(C, W, H)` rather than transposing one plane. The
implementation drops the channel axis before calling the hand-written loop.

The hand-written version allocates the destination with the swapped shape and
assigns each pair of indices:

```python
rows, columns = arr.shape
out = np.empty((columns, rows), dtype=arr.dtype)
for i in range(rows):
    for j in range(columns):
        out[j, i] = arr[i, j]
```

This is `rows * columns` Python-level assignments. For a 400 by 400 crop the loop
takes about 0.025 s, while `.T` takes about 8e-8 s because it only builds a new
header. The subject forbids the library transpose for that reason: writing the
double loop makes the `O(H·W)` work visible instead of hiding it behind a
constant-time metadata change.

The loop also exposes memory order. The read `arr[i, j]` walks a row contiguously
as `j` increases, but the write `out[j, i]` jumps one full row of `out` per step.
The reverse loop order would make the writes contiguous and the reads strided;
without blocking or tiling, one side walks with a large stride. On a
4000 by 4000 `float64` array the strides are `(32000, 8)`, so moving down one column
advances 32000 bytes, or 500 lines at 64 bytes per line, while using eight bytes
from each line. Copying the transposed view takes about 0.03 s versus 0.012 s for
the contiguous copy: same elements, two to three times the time from the access
pattern.

`np.empty` allocates the destination without initialising it. A loop that writes
every index is safe, but one that skips an index leaves arbitrary bytes in the
output; reading `np.empty(16)` immediately shows non-zero values. The dtype
argument matters too: `dtype=arr.dtype` keeps `uint8` and the same eight-bit
contract, while the default float would multiply the buffer size by eight and
change the values the caller sees.

A square crop hides shape bugs. The destination shape is `(columns, rows)`; with
400 and 400 the two orders are indistinguishable, so an allocation written as
`(rows, rows)` still passes. A non-square test catches the error. The same crop also
shows why `cropped[:, :, 0]` is safer than `squeeze()`: it removes exactly the
channel axis, whereas `squeeze()` would also remove a spatial axis of length one.

The hand-written result can be checked against `arr.T` in a test; using `.T` as an
oracle is different from using it as the implementation. `np.array_equal` on the
two arrays returns true for the same input.

## How to check

Run the program from `ex04` with the Agg backend and a timeout. Expect the warning,
the loaded shape, the original pixel dump, the new transpose shape and the
transposed pixel data.

```bash
cd Module_1/ex04
MPLBACKEND=Agg timeout 30 ../.venv/bin/python rotate.py
cd .. && make lint
```

The output starts with `UserWarning: FigureCanvasAgg is non-interactive, and thus
cannot be shown`, then `The shape of image is: (768, 1024, 3)`, then the original
pixels, then `New shape after Transpose: (400, 400)` and the transposed pixels.
It does not print the cropped shape. The warning is expected from the Agg canvas.
`make lint` from the module root exits 0 with no diagnostics;
`.venv/bin/flake8 ex04` is the per-exercise form.

## Key take away

A transpose swaps shape and strides; the library version is metadata-only, and the
hand-written version makes the `O(H·W)` assignments visible. Allocate with the
destination shape, preserve the dtype and write every cell. One side of a naive
transpose walks memory with a large stride, which is why layout matters as much as
operation count. Remove only the axis that should disappear, because `squeeze()`
can remove more. Use the forbidden call as a test oracle, never as the
implementation.
