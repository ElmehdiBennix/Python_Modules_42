# Exercice 03 — Zoom on me

## The problem

`zoom.py` loads `animal.jpeg`, prints the size in pixels on both axes, the number
of channels and the pixel content, then cuts a square region out of the image,
prints its new shape and displays it with the axis scales visible. Failures must
produce a clear message instead of stopping the program. The subject shows the
original shape as `(768, 1024, 3)` and accepts either `(400, 400, 1)` or
`(400, 400)` for the crop; this implementation keeps the channel axis and prints
`(400, 400, 1)`.

## The concept

The array shape encodes the picture as height, width, channel. For
`(768, 1024, 3)` the strides are `(3072, 3, 1)`: 1024 pixels times three channels
gives 3072 bytes per row, three bytes per pixel, one byte per channel. The crop
`img[100:500, 450:850, 0:1]` applies a half-open range to each axis, selecting rows
100 to 499, columns 450 to 849 and channel 0 only. The result has shape
`(400, 400, 1)` and strides `(3072, 3, 1)`; its data pointer is offset by
`100*3072 + 450*3` bytes.

That is a view. The slice does not copy 160,000 pixels; it creates a new array
object over the same buffer.

```python
crop = img[100:500, 450:850, 0:1]   # (400, 400, 1), shared buffer
print(crop.shape)
```

Writing to `crop[0, 0, 0]` changes `img[100, 450, 0]`, and `np.shares_memory`
reports true. A later operation that needs contiguous data, such as saving or
calling a library that invokes `ascontiguousarray`, may allocate a copy, but the
slice itself does not.

The channel slice decides the rank. `img[:, :, 0:1]` keeps an axis of length one, so
the shape is `(400, 400, 1)`. `img[:, :, 0]` indexes the channel axis and removes it,
so the shape is `(400, 400)`. Both are accepted and contain the same values, but
they are different objects with different ranks. `squeeze()` removes every axis of
length one, not just the channel axis; on a one-pixel-wide crop it can collapse the
result below two dimensions.

Displaying is a second transformation. `imshow` reads a three-dimensional array as
RGB. A two-dimensional array is scalar intensity, and an `(H, W, 1)` array is one
scalar channel; both need `cmap="gray"` to map values to a grey ramp. This
implementation calls `squeeze()` for display only and returns a three-dimensional
crop.

Matplotlib copies the data it draws: its normalisation calls
`safe_masked_invalid(A, copy=True)`, so the array stored by the `AxesImage` does not
share memory with the view passed to `imshow`. A non-contiguous crop therefore
displays without a manual `ascontiguousarray`; the display path performs the copy.

```python
plt.imshow(crop.squeeze(), cmap="gray")
plt.show()
```

`aspect` changes what the axes mean. `imshow` defaults to equal aspect, reported as
`1.0`, so one pixel is square and a 400 by 400 crop fills a square box.
`aspect="auto"` stretches the data to fill the axes rectangle, so apparent geometry
follows the figure rather than the pixel grid. The pixels do not change. The subject
asks for visible scales, so the axes stay on; `plt.axis("off")` would remove the
ticks and labels that constitute the scale.

Coordinates are validated before slicing: two integers per tuple, non-negative
starts, ends within the image, and each start strictly less than its end. A failure
prints a message and returns an empty array, and `main` tests `.size` before
displaying. Swapping the tuples is the common misuse: x is the column and y is the
row, so a swapped crop selects another region or raises `IndexError`.

## How to check

Run the program from `ex03` with the Agg backend and a timeout, because `plt.show()`
would otherwise wait for a window. Expect the non-interactive warning, the original
shape, the cropped shape and two large array dumps.

```bash
cd Module_1/ex03
MPLBACKEND=Agg timeout 30 ../.venv/bin/python zoom.py
cd .. && make lint
```

The output starts with `UserWarning: FigureCanvasAgg is non-interactive, and thus
cannot be shown`, then `The shape of image is: (768, 1024, 3)`, the original pixels,
`New shape after slicing: (400, 400, 1)` and the cropped pixels. The warning is
expected: the Agg canvas cannot open a window. `make lint` from the module root
exits 0 with no diagnostics; `.venv/bin/flake8 ex03` is the per-exercise form.

## Key take away

Slicing an image is slicing three axes at once, and the channel slice decides
whether that axis survives. A crop is a view until a library copies it, so writing
to it can change the source. `squeeze()` removes every length-one axis, which is
more than the channel axis. Plotting uses a different axis order and colour
convention from NumPy, and `axis("off")` removes the scale the subject requires. A
headless display needs a backend choice and a timeout.
