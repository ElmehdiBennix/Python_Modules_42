# Exercice 06 — Morse code

## The problem

The program turns exactly one command-line string into Morse code. Each letter
becomes dots and dashes, characters are separated by one space, and a literal
space becomes a slash. Lower-case input is accepted and uppercased first. A
wrong argument count or a character missing from the table prints
`AssertionError: the arguments are bad` and nothing else, so no partial
transcript may reach the screen.

## The concept

The table `NESTED_MORSE` maps every supported character to a code that already
ends with a space. Joining the values in order therefore produces the
separators for free, and only the final trailing space has to be removed:

```python
print("".join(NESTED_MORSE[char] for char in text).rstrip())
```

The `.upper()` call happens before the lookup, because the table stores capital
letters. Without it, `sos` raises `KeyError` even though the alphabet is
present.

Validation is a separate pass over the whole string. The program walks the
upper-cased text, confirms every character is a key, and only then builds the
output. Printing inside the first loop would emit the code for `H` and then
crash on `$` in `h$llo`, leaving half a line behind and no clean error message.

Shell quoting decides what the program actually receives. Single quotes keep a
dollar sign literal, so `'h$llo'` reaches Python as five characters and is
rejected. Double quotes let the shell expand `$llo` as a variable, so the
program sees a different, shorter string and the test measures the wrong thing.

## How to check

Run the encoding and expect the codes with no space before the end of line,
which `cat -e` shows as `$`. Run the rejected character and expect only the
assertion line. Run the two-word input and expect a slash between the words.

```bash
cd Module_0/ex06
python3 sos.py "sos" | cat -e      # ... --- ...$
python3 sos.py 'h$llo'             # AssertionError: the arguments are bad
python3 sos.py "sos 42" | cat -e   # ... --- ... / ....- ..---$
cd .. && .venv/bin/flake8 ex06/sos.py
```

Expect nothing from the lint command: a clean file prints nothing.


The table-driven construction can be checked independently:

```bash
python3 -c "m={'S':'...','O':'---'}; print(' '.join(m[c] for c in 'SOS'))"
... --- ...
```

The exercise table stores a trailing separator in every code, then removes
only the final one with `rstrip`. This design handles the literal-space
mapping `/` using exactly the same join path as letters and digits. Uppercase
normalisation means `sos` and `SOS` use the same keys.

Validation must happen before construction. If an unsupported character is
found, the program prints one assertion line and returns; it does not expose
the valid prefix. This is especially visible with shell metacharacters.
Single quotes preserve a dollar sign for Python, whereas double quotes allow
the shell to expand it. The command line is therefore part of the input
fixture, and quoting belongs in a reproducible test.

## Key take away

Storing the separator inside each value simplifies joining and leaves exactly
one cleanup step at the end. Validate the entire input before producing output,
so failures are atomic from the caller's point of view. Normalising case before
a lookup removes a whole class of missing-key errors. Quoting is part of the
test, and a dollar sign in double quotes is not the character the program
receives. A table-driven encoder keeps the alphabet in data rather than in
control flow.
