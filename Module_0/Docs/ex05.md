# Exercice 05 — Counting characters

## The problem

The program takes one string, either as the single command-line argument or
from standard input, and reports how many characters it contains, split into
upper-case letters, lower-case letters, punctuation marks, spaces and digits.
With no argument it prints `What is the text to count?` and reads until end of
file. With more than one argument it prints
`AssertionError: more than one argument is provided` and stops. The six output
lines are fixed, and the counts are always plural, including
`1 punctuation marks`. Validation happens before any counting output.

## The concept

`sys.stdin.read()` returns everything up to end of file, and it keeps the final
newline. That newline is whitespace, so `char.isspace()` counts it as a space,
which is why `echo "Hello World!" | python3 building.py` reports 13 characters
and 2 spaces while `printf "Hello World!"` reports 12 and 1. The subject wants
the carriage return counted, so the difference is correct.

`input()` is the wrong tool for the piped path. It strips the trailing newline
and raises `EOFError` when the stream is already at end of file, whereas
`read()` simply returns `""`. Printing the prompt and then reading the raw
stream keeps both behaviours under control and places the text on the next
line.

The counting loop is a chain of `if`/`elif`. Upper and lower case are checked
before the generic whitespace test, digits use `isnumeric()`, and punctuation
is the final `else`, so every character lands in exactly one bucket. Because
no character is dropped, the five counts add up to the total length.

## How to check

Run the argument form and expect 12 characters and 1 space. Run the pipe with
`echo` and expect one extra character and one extra space for the newline. Run
the two-argument form and expect the assertion line only.

```bash
cd Module_0/ex05
python3 building.py "Hello World!"              # 12 characters, 1 spaces
printf "Hello World!" | python3 building.py     # 12 characters, 1 spaces
echo "Hello World!" | python3 building.py       # 13 characters, 2 spaces
python3 building.py 13 5                        # AssertionError line
cd .. && .venv/bin/flake8 ex05/building.py
```

Expect nothing from the lint command: a clean file prints nothing.


The stream boundary can be demonstrated without changing the program:

```bash
printf 'A 7!' | python3 building.py
What is the text to count?
The text contains 4 characters:
1 upper letters
0 lower letters
1 punctuation marks
1 spaces
1 digits
```

The prompt is printed before the read, and `sys.stdin.read()` then consumes
the complete stream. A newline added by `echo` becomes another whitespace
character. `printf` is useful when the demonstration needs exact control over
the final byte. `read()` also returns an empty string at end of file without
raising `EOFError`, which makes the pipe and redirected-file cases uniform.

Each character reaches one branch. Uppercase and lowercase checks happen
before the generic whitespace check; numeric characters use `isnumeric`, and
the final branch counts the remaining characters as punctuation. This
classification includes Unicode behavior supplied by Python's string methods,
not only ASCII. The total length is a simple invariant: adding the five
reported counts must reproduce it.

## Key take away

Reading a stream and reading a line are different operations with different
edge cases, and the choice changes the count by one. Shell tools add invisible
characters, so compare piped output with `printf` when a newline is not wanted.
A classification chain should cover every element exactly once, which the total
makes checkable. Plural wording in a specification is a literal requirement,
not a grammar suggestion. Validate before printing so a rejected input produces
one line rather than a partial report.
