# Exercice 08 — Recoding filter

## The problem

The task is to write `ft_filter(function, iterable)` so it matches the built-in
`filter`, including the lazy part. It has to be a generator that yields matching
items one at a time, it has to treat `None` as the truthiness test, and its
docstring has to equal `filter.__doc__` byte for byte. Iterating the result has
to produce the same sequence as the built-in for the same arguments.

## The concept

A function containing `yield` is a generator function. Calling it does not run
the body; it returns a generator object, and each `next()` runs until the next
`yield`. That is why `list(ft_filter(...))` shows the full sequence, and why an
unbounded iterable is safe when only a few items are taken.

When `function` is `None`, the built-in keeps items that are truthy. The short
equivalent is `if function is None: function = bool` before the loop, which
turns one flag into an ordinary callable and leaves a single test in the body.
Replacing `None` with a lambda that always returns true is not equivalent; the
truthiness test is the point.

The docstring is data. Continuation lines that are indented to match the
function body carry those spaces into `__doc__`, so the comparison fails. The
text also belongs to the running Python version, so the reliable source is the
interpreter itself:

```bash
python -c "print(repr(filter.__doc__))"
```

Errors follow the same laziness. A non-iterable argument raises `TypeError` at
the first `next()`, not at call time, because the body has not started; the
built-in raises immediately. Importing the module prints nothing.

## How to check

Run the even-number call and expect `[0, 2, 4, 6, 8]`. Run the `None` case and
expect the truthy items `1`, `'a'` and `2`. Run the docstring comparison and
expect `True`.

```bash
cd Module_0/ex08
python3 -c "from ft_filter import ft_filter; \
print(list(ft_filter(lambda x: x % 2 == 0, range(10))))"   # [0, 2, 4, 6, 8]
python3 -c "from ft_filter import ft_filter; \
print(list(ft_filter(None, [0, 1, '', 'a', None, 2])))"    # [1, 'a', 2]
python3 -c "import ft_filter as m; print(m.ft_filter.__doc__ == filter.__doc__)"  # True
cd .. && .venv/bin/flake8 ex08/ft_filter.py
```

Expect nothing from the lint command: a clean file prints nothing.


Generator timing is visible with a small instrumented function:

```bash
python3 -c "def g(): print('body'); yield 1; print('done'); x=g(); print('created'); print(next(x))"
created
body
1
```

Calling `g()` creates the generator but does not print `body`. The first
`next()` starts execution, runs to the yield, and pauses there. A later
`next()` would resume after the yield and print `done` before finishing. This
same timing explains why an error from a bad iterable can be delayed until
iteration for a generator implementation.

`filter` treats `None` specially by applying truth testing, not by accepting
every item. Replacing `None` with `bool` preserves that contract and keeps
the loop uniform. Generator objects are single-use iterators, so converting
one to a list consumes it. Finally, a docstring is an ordinary string with
significant whitespace; the function's `__doc__` must match the running
interpreter's `filter.__doc__`, including line breaks and indentation.

## Key take away

Laziness is a property of when the body runs, and it changes when errors
surface as well as when values appear. A generator is consumed once, so a
second pass over the same object is empty by design. Substituting a concrete
default for a sentinel keeps the hot loop simple. Docstrings are strings, and
their whitespace is part of the value. Copying interpreter-provided text is
more reliable than transcribing it from a PDF.
