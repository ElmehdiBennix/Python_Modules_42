# Exercice 04 — Even or odd

## The problem

The program takes at most one command-line argument, converts it to an integer,
and prints whether it is even or odd. With no argument it prints nothing at
all. With more than one argument it prints
`AssertionError: more than one argument is provided`, and with a value that is
not an integer it prints `AssertionError: argument is not an integer`. Those
two messages are different, and the successful answers are exactly
`I'm Even.` and `I'm Odd.`, capital `I`, full stop included.

## The concept

`sys.argv` is a list of strings: the first entry is the script name and the
first real argument is `sys.argv[1]`. Nothing converts automatically, so the
program decides when to parse and how to report failure. `int()` raises
`ValueError` on anything that is not an integer literal, and that exception is
the validation mechanism. It tolerates surrounding whitespace and a leading
sign, which is why `" 8 "` converts.

Once the value is an integer, `% 2` gives the parity. Python's modulo follows
the sign of the divisor, so `-5 % 2` is `1` and `-5` is odd; no `abs()` is
needed. `0 % 2` is `0`, so zero is even.

Ordering carries the exercise. Counting arguments comes first, then parsing,
then computing. Parsing before counting turns a missing argument into an
`IndexError` traceback where the subject expects silence. A branch placed after
an earlier `return` is unreachable, and dead code usually signals a condition
that was written for the wrong case.

## How to check

Run the program once per case and expect the comment on each line. Run the
no-argument case in a shell and expect no output, not a traceback.

```bash
cd Module_0/ex04
python3 whatis.py 14        # I'm Even.
python3 whatis.py -5        # I'm Odd.
python3 whatis.py 0         # I'm Even.
python3 whatis.py           # nothing
python3 whatis.py Hi!       # AssertionError: argument is not an integer
python3 whatis.py 13 5      # AssertionError: more than one argument is provided
cd .. && .venv/bin/flake8 ex04/whatis.py
```

Expect nothing from the lint command: a clean file prints nothing.


`sys.argv` is easy to inspect without a file:

```bash
python3 -c "import sys; print(sys.argv)" alpha beta
['-c', 'alpha', 'beta']
```

Every user argument is text. Conversion boundaries can be observed directly:

```bash
python3 -c "print(int(' 8 ')); print(int('-5'))"
8
-5
```

Whitespace and a sign are accepted by `int`, while a value such as `12x`
raises `ValueError`. The program catches that expected validation failure and
prints its required message. It checks the argument count first because
`sys.argv[1]` does not exist in the no-argument case. A no-argument run is
defined as silence, not as an error.

Modulo uses floor-division arithmetic rather than a bit operation. Since
`-5 % 2` is `1`, the odd branch works for negative input without special
normalisation. The successful output is deliberately fixed text, so both the
apostrophe and the final full stop belong to the interface.

## Key take away

Command-line input is text until the program converts it, and the conversion
point is the validation point. Counting arguments before indexing them turns a
crash into a message. Python's modulo is arithmetic rather than a bit mask, so
negative numbers behave predictably. A branch after an unconditional `return`
cannot run, and noticing that saves a debugging session. Exact strings,
including punctuation and case, are part of the interface.
