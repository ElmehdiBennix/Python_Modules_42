# Exercice 03 — Data class

## The problem

The exercise asks for a `Student` dataclass built from a `name` and a
`surname`. The object must set `active` to `True`, derive a `login` from the
name and surname, and generate a random fifteen-letter lowercase `id` with
the supplied `generate_id` function. The derived fields must not be accepted
as constructor arguments.

The subject's first tester is:

```python
student = Student(name="Edward", surname="agle")
print(student)
```

The expected representation has the generated values in dataclass field order:

```text
Student(name='Edward', surname='agle', active=True, login='Eagle', id='...')
```

The identifier changes because it is random. The second tester passes
`id="toto"` and must raise:

```text

```

## The concept

`@dataclass` is a class decorator that reads annotated fields and generates
standard methods such as `__init__`, `__repr__`, and `__eq__`. The generated
constructor accepts fields whose `init` option is true. This lets the class
declare which values callers provide and which values the class derives.

The input fields are `name` and `surname`. `active` is a defaulted field with
the value `True`. `login` and `id` use `field(init=False)`, so they appear in
the printed dataclass representation but do not appear in the constructor
signature. They are assigned after the input fields exist, normally in
`__post_init__`, which the generated `__init__` calls automatically.

The login follows the subject's case rule: the first character of `name` is
lowered or uppered according to the required expression, then the surname is
combined with it. For the supplied values, the expected login is `Eagle`.
The exact transformation belongs in the implementation and must be checked
against the subject examples rather than guessed from the field name.

`generate_id` uses `random.choices(string.ascii_lowercase, k=15)`. It returns
a fresh string each time, so the object can be compared for its fixed fields
without expecting two random identifiers to match. The function is supplied
by the exercise and is not replaced by a deterministic value.

The exercise also demonstrates generated representation. The subject forbids
writing `__str__` or `__repr__`; `print(student)` uses the dataclass-generated
`__repr__`. The field declaration order controls the displayed order. A
field that is derived but marked `init=False` can still be displayed, which
separates construction policy from representation policy.

## Key take away

Dataclasses turn annotated state into a constructor and representation, while
`field(init=False)` separates caller input from derived state. Use
`__post_init__` for values that require initialized fields, preserve the
generated `__repr__`, and test both normal construction and forbidden
constructor arguments. Random output needs structural checks rather than one
hard-coded identifier.
