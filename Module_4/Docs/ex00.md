# Exercice 00 — Calculate statistics

## The problem

`ft_statistics(*args, **kwargs)` receives an unknown quantity of numbers and an
unknown set of keyword arguments whose values name the statistics to compute:
`mean`, `median`, `quartile`, `std` and `var`. Each recognised value prints one
line as `name : value`, with a space before the colon. A value outside that list
prints nothing, and when there are no numbers every recognised request prints
`ERROR`. The allowed functions are `None`: no `statistics`, no `numpy`. The
tester's first call is `ft_statistics(1, 42, 360, 11, 64, toto="mean",
tutu="median", tata="quartile")`; the keys are arbitrary, so the implementation
must read the values.

## The concept

`*args` arrives as a tuple and `**kwargs` as a dict. The keys are whatever the
caller wrote, so `toto="mean"` and `mean="mean"` are the same request. Branching
on `"mean" in kwargs` tests the wrong side: the name `mean` lives in a value, not
in a key. `kwargs.values()` reads the requests in call order, and a dict from
statistic name to function turns each request into a lookup. A name that is not a
string, or is not in the dict, is skipped. That is the exercise's stated
behaviour: unknown names print nothing. It is a deliberate decision to ignore
unknown requests rather than raise, so validation operates on values, not on the
keyword names.

An empty `args` is not "zero data" that should produce `0`; it is an error
condition. `sum(data) / len(data)` raises `ZeroDivisionError` on an empty
sequence, and the median and quartile have no index to read. The subject asks for
one `ERROR` line per recognised request, so the guard runs before the handler: if
the sorted data is empty, print `ERROR` and continue to the next request. A mixed
tuple that cannot be sorted is caught at the same boundary and treated as empty,
which produces the same `ERROR` rather than a traceback.

Mean, median and quartiles are order statistics: they read positions in a sorted
copy, not the order the caller supplied. `sorted(args)` returns a new list, so
the tuple is untouched. The median is the middle element for an odd count and the
average of the two middle elements for an even one. The quartiles follow the same
idea at the quarter and three-quarter positions. Variance and standard deviation
are different: they sum squared deviations from the mean over every value, then
divide and take a root. The divisor is the convention. Dividing by `n` gives the
population variance; dividing by `n - 1` gives the sample variance and a larger
number. The recorded second call has population variance
`323377543.9183673` and sample variance `377273801.2380952`, so the choice is
visible in the transcript. The code divides by `n`, which is why it matches the
subject.

Quartile convention is not universal. The code interpolates at `p * (n - 1)`,
which for five values lands exactly on indices one and three and returns
`[11.0, 64.0]`. The subject's expected value also matches the median-of-halves
convention: with the centre included, the lower half is `[1, 11, 42]` and the
upper half is `[42, 64, 360]`, whose medians are `11` and `64`. The two
conventions agree on five values and diverge on four: interpolation gives
`[8.5, 47.5]` while median-of-halves gives `[6.0, 53.0]`. A reader who assumes
one convention explains both outputs only by accident. Read the expected output
before choosing, and state the choice in the docstring.

## Key take away

Read the signature before the body: `*args, **kwargs` leaves both the number of
values and the set of requests open, so every branch must tolerate absence.
Validate the values, because the keys belong to the caller. Sort before
indexing, and settle the divisor and the quartile convention from the expected
output. When an unknown request is meant to be ignored, say so; when empty input
is an error, print the error once per request rather than once per call.
