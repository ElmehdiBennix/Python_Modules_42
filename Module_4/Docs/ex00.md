# Exercice 00 — Calculate statistics

## The problem

`ft_statistics(*args, **kwargs)` receives an unknown quantity of numbers and an
unknown set of keyword arguments whose values name the statistics to compute:
`mean`, `median`, `quartile`, `var` and `std`. Each recognised value prints one
line as `name : value`, with a space before the colon. A value outside that list
prints nothing at all. When there are no usable numbers, every recognised request
prints `ERROR`. The allowed functions are `None`: `statistics` and `numpy` are
both forbidden, so every formula is written by hand.

The tester's keys are arbitrary (`toto`, `tutu`, `tata`). They carry no meaning;
the requests live in the values.

## The concept

`*args` arrives as a tuple and `**kwargs` as a dict. Branching on the keywords
would test the wrong side of the mapping: `toto="mean"` asks for the mean, and
`mean="mean"` would ask for exactly the same thing. Reading `kwargs.values()`
keeps the call order and makes each request independent of the name the caller
chose.

A dict from statistic name to function turns each request into one lookup. A name
that is not a string, or is not in the dict, is skipped. That is a deliberate
decision to ignore unknown requests rather than raise, which is why the third call
of the tester prints nothing between its separators.

An empty `args` is an error condition, not zero data. `sum(data) / len(data)`
raises `ZeroDivisionError`, and the median and quartile have no index to read. The
guard therefore runs before the handler: if the sorted data is empty, print
`ERROR` and move to the next request. A tuple that cannot be sorted is caught at
the same boundary and treated as empty, which produces the same `ERROR` instead of
a traceback.

Mean, median and quartiles are order statistics: they read positions in a sorted
copy, not the order the caller supplied. `sorted(args)` returns a new list, so the
original tuple is untouched. The median is the middle element for an odd count and
the average of the two middle elements for an even one. Variance and standard
deviation are different: they sum squared deviations from the mean over every
value, then divide and take a root.

The divisor is a convention, not a detail. Dividing by `n` gives the population
variance, dividing by `n - 1` gives the sample variance and a larger number. The
expected output `323377543.9183673` matches the population divisor, so the choice
is visible in the transcript rather than hidden in the code.

The quartile convention is not universal either. The implementation interpolates
at `p * (n - 1)`, which for five values lands exactly on indices one and three and
returns `[11.0, 64.0]`. On four values the same rule does not land on a sample:
`1, 11, 42, 64` gives `[8.5, 47.5]`, while a median-of-halves convention would
give `[6.0, 53.0]`. Reading the expected output before choosing the formula is
the only way to pick one deliberately.

## How to check

Run the tester from its directory. Every line below is the real output.

```bash
cd Module_4/ex00
../.venv/bin/python tester.py
# mean : 95.6
# median : 42
# quartile : [11.0, 64.0]
# -----
# std : 17982.70124086944
# var : 323377543.9183673
# -----
# -----
# ERROR
# ERROR
# ERROR
```

The third call requests only unknown names, so it prints nothing and only the
tester's separator appears. The fourth call supplies no numbers, so each of its
three recognised requests produces one `ERROR`.

The interpolation rule can be watched on a four-value set:

```bash
../.venv/bin/python -c \
  "from statistics import ft_statistics; ft_statistics(1, 11, 42, 64, q='quartile')"
# quartile : [8.5, 47.5]
```

The subject requires a docstring on every function, including the nested helpers:

```bash
../.venv/bin/python -c \
  "from statistics import ft_statistics; print(ft_statistics.__doc__)"
```

Lint from the module root:

```bash
cd Module_4
.venv/bin/flake8 ex00 ex01 ex02 ex03
```

Expect nothing from the lint command: a clean tree prints nothing. flake8 cannot
check the documentation rule, which is why the `__doc__` audit stays manual.

## Key take away

Read the signature before the body: `*args, **kwargs` leaves both the number of
values and the set of requests open, so every branch must tolerate absence.
Validate the values, because the keys belong to the caller. Sort before indexing,
and settle the divisor and the quartile convention from the expected output
rather than from habit. When an unknown request is meant to be ignored, say so; when
empty input is an error, print the error once per request, not once per call.
