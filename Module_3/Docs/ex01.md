# Exercice 01 — GOT S1E7

## The problem

Two more houses, `Baratheon` and `Lannister`, inherit from `Character` and must
be instantiable without going through the abstract base. Each carries a family
name, an eye colour and a hair colour, and each needs `__str__` and `__repr__`
that return strings rather than objects. `Lannister` also gains a class method
`create_lannister` that builds a character in a chain from the class itself.

## The concept

`print(obj)` calls `str(obj)`, which asks the type for `__str__`. When the class
has no `__str__`, Python falls back to `__repr__`: a class that defines only
`__repr__` and returns `'R'` makes both `str(x)` and `print(x)` produce `R`. The
two hooks serve different audiences. `__str__` is the readable form used by
`print` and `str`; `__repr__` is the unambiguous form used by `repr`, by the
text of containers, and by the default object display. `__repr__` is the one
that must always exist, because it is the fallback.

Both hooks must return a `str`. The interpreter checks the return value after
the call and raises if it is anything else. A `__str__` that returns `self`
produces `TypeError: __str__ returned non-string (type Baratheon)`; a `__repr__`
that returns `self` produces `TypeError: __repr__ returned non-string (type
Baratheon)`. That is exactly the failure the exercise warns about: returning the
object instead of a description does not print the object, it aborts the print.
The current implementations return f-strings, so they pass.

The current strings also differ from the subject sample. `__str__` produces
`Baratheon Robert: brown eyes and dark hairs is alive`, while `__repr__`
produces `Vector: ('Baratheon', 'brown', 'dark')`; the subject shows
`'Baratheon'` with a capital B and does not print either rendered string. The
requirement is the return type, and the repository satisfies it. The family
name uses the subject's required capitalization, `Baratheon`.

The tester prints `Robert.__str__`, not `Robert.__str__()`. The attribute is a
bound method, `type(...)` prints `<class 'method'>`, and its text includes the
representation of the instance:
`<bound method Baratheon.__str__ of Vector: ('Baratheon', 'brown', 'dark')>`.
The `Vector:` fragment comes from `__repr__`, called to describe the instance
inside the bound method. `__str__` never runs. That is why the recorded output
shows a representation even though the tester never asks for one directly.

`@classmethod` is a descriptor. The decorator wraps the function in a
`classmethod` object, and that object's `__get__` returns a bound method whose
first argument is the class rather than an instance. `Lannister.create_lannister`
therefore has `__self__` equal to `<class 'S1E7.Lannister'>`, and calling it runs
`cls(first_name, is_alive)` with `cls` already supplied. No instance is needed
to reach the method, which is why it can serve as an alternative constructor.
It is not a factory in disguise: it does not inspect its arguments and choose a
type. It forwards to whatever class the attribute was read from, so a subclass
that inherits it gets the subclass back. That is the useful part of binding
`cls` instead of hard-coding `Lannister`.

`Baratheon` and `Lannister` each define `die`, which clears the inherited
abstract name: `Baratheon.__abstractmethods__` prints `frozenset()`. Their
constructors call `super().__init__` first and then write their own traits, so
the base fields exist before the family fields are added.

The tester must run inside the exercise directory so `S1E7` and `S1E9` resolve
locally.

The subject prints `'Baratheon'` with a capital B; this repository stores
`'Baratheon'` and prints it with the subject's capitalization. That is a data difference, not a
mechanism difference.

## Key take away

A subclass becomes concrete by answering every abstract name. Representation
dunders are called by the language, not by the author, and their return type is
checked. `str` falls back to `__repr__`, so a missing `__str__` is survivable
while a missing `__repr__` leaves the default object address. A class method is
a constructor that knows the class it was called on, which is stronger than a
function that happens to return an instance. Printing a method object shows the
method and the object it is bound to, not the method's result.
