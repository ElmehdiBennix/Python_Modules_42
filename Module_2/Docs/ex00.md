# Exercice 00 — Load my Dataset

## The problem

We implement `load(path)` as the boundary between a file and the exercises
that analyse it. The current function returns a `DataFrame` for an existing
CSV and `None` for an absent path, a directory, a non-CSV suffix, or a read
failure. It prints `1`, `2`, or `3` for those failure gates. We also notice
the code drift: it does not print the requested dimensions, and its unused
imports and exception variable contribute to lint failures. The module keeps a
`__main__` guard, so importing `load` does not execute the sample call.

## The concept

`pd.read_csv` parses rows into columns, but it infers each column independently.
It does not know that a header such as `1900` is a number: headers are strings.
It also does not guarantee that cells are numeric. Life expectancy is numeric
with missing values, while population stores values such as `29M`; income can
change dtype when later years contain suffixes. We verify these facts against
the actual files:

```bash
.venv/bin/python -c "import pandas as pd; p='subject/life_expectancy_years.csv'; d=pd.read_csv(p); print(d.shape, type(d.columns[1]).__name__, d['1900'].dtype, int(d.isna().sum().sum()))"
# (195, 302) str float64 2079
.venv/bin/python -c "import pandas as pd; a=pd.read_csv('subject/income_per_person_gdppercapita_ppp_inflation_adjusted.csv'); print(a['1900'].dtype, a['1901'].dtype)"
# int64 object
```

The optional `index_col=0` argument changes the table's organization. It
installs the first field, `country`, as the index rather than throwing it away.
The dimensions change from `(195, 302)` to `(195, 301)`, and the country label
becomes available to `.loc`:

```bash
.venv/bin/python -c "import pandas as pd; p=pd.read_csv('subject/life_expectancy_years.csv'); d=pd.read_csv('subject/life_expectancy_years.csv',index_col=0); print(p.shape, d.shape, d.index.name, d.loc['France'].shape)"
# (195, 302) (195, 301) country (301,)
```

This distinction explains why ex00's unindexed sample has 302 columns while
the later exercises' loaders have 301. `reset_index()` reverses the decision.
The index is a label axis, not an ordinary data column, and alignment uses
those labels. A loader should make that decision explicit because downstream
selection depends on it.

The path checks and the parser check answer different questions. `Path.is_file`
rejects a missing name or directory. The suffix check enforces a local policy,
but it does not prove that the contents are CSV: a valid CSV renamed `.txt`
would still be rejected. Conversely, a `.csv` file can be unreadable. The
current code catches the parser exception and returns `None`; for ordinary
calls, callers can branch instead of handling an exception. We can observe the
current digits and return values:

```bash
cd Module_2/ex00
../.venv/bin/python -c "from load_csv import load; print(load('nope.csv'))"
# 1
# None
../.venv/bin/python -c "from load_csv import load; print(load('../subject/en.subject.pdf'))"
# 2
# None
```

The PDF probe reaches the suffix gate before pandas can report its decoding
error. This ordering is useful for teaching control flow, but the digits are
opaque to a caller. The subject also asks for a dimensions message; the
current `main` prints pandas' frame representation instead, whose final line
is `[195 rows x 302 columns]`. We describe that drift rather than pretending
the request is already met.

## How to check

From `Module_2/ex00`, run:

```bash
../.venv/bin/python load_csv.py
../.venv/bin/python -c "from load_csv import load; d=load('../subject/life_expectancy_years.csv'); print(d.shape if d is not None else None)"
cd .. && .venv/bin/flake8 ex00
```

The first command exits 0 and prints the unindexed frame. The second confirms
`(195, 302)`. The current lint run reports three findings: the unused
`logging.exception` import, the unused `e`, and a missing blank line before the
guard. These are known code issues; this documentation does not modify Python.

## Key take away

We keep loading separate from analysis, validate the path before parsing, and
return a documented failure value. We remember that dtype inference is
column-wise, headers are strings, and `index_col=0` changes the shape and the
lookup vocabulary. We distinguish a suffix policy from a content test, and we
report the current dimension-message and lint drift accurately.
