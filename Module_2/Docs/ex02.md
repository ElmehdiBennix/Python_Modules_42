# Exercice 02 — compare my country

## The problem

We compare France and Belgium's population from 1800 through 2050. We need two
lines, a title, labelled axes, readable population units, and a legend that
identifies each line. The current program does this for the selected countries,
but its conversion handles only values ending in `M`; it is not a general
population parser. The script itself is guarded by `__main__`.

## The concept

The population table is wide and its cells are strings with unit suffixes.
`read_csv` correctly reads the file, but `object` dtype means “mixed or
text”, not “already numeric”:

```bash
.venv/bin/python -c "import pandas as pd; d=pd.read_csv('subject/population_total.csv',index_col=0); print(d.shape, d.loc['France'].dtype, d.loc['France'].iloc[[0,-1]].tolist())"
# (197, 301) object ['29M', '65.5M']
```

The current lambda removes `M` and multiplies by one million. That works for
France and Belgium, but the file also contains `k` and `B`. We demonstrate
why a country-specific conversion is fragile:

```bash
.venv/bin/python -c "import pandas as pd; d=pd.read_csv('subject/population_total.csv',index_col=0); print(int(d.apply(lambda r: r.astype(str).str.contains('k').any(),axis=1).sum())); d.loc['Albania'].apply(lambda x: float(x.replace('M',''))*1e6)"
# 119
# ... ValueError: could not convert string to float: '400k'
```

Without conversion, a string reduction can concatenate rather than add:

```bash
.venv/bin/python -c "import pandas as pd; d=pd.read_csv('subject/population_total.csv',index_col=0); print(d.loc['France'].sum()[:18])"
# 29M29.1M29.2M29.3M
```

We filter years by labels. Because every year label has four digits,
`"1800" <= label <= "2050"` follows chronological order. The mask keeps 251
labels, while the tick stride of 20 only chooses which labels to display. The
selection and the presentation are different jobs:

```bash
.venv/bin/python -c "import pandas as pd; d=pd.read_csv('subject/population_total.csv',index_col=0); s=d.loc['France']; y=s.index[(s.index>='1800')&(s.index<='2050')]; print(len(y), y[0], y[-1], len(y[::20]))"
# 251 1800 2050 13
```

Two calls to `plot` add two line artists to one `Axes`. The `label=` values
give `legend()` handles to collect, so plotting order controls legend order.
The y data remains people; a `FuncFormatter` divides displayed values by
`1e6` and appends `M`. We can inspect the current figure with Agg:

```bash
MPLBACKEND=Agg .venv/bin/python -c "import matplotlib.pyplot as plt; f,a=plt.subplots(); a.plot([1,2],label='Belgium'); a.plot([2,3],label='France'); a.legend(); print(len(a.lines), [t.get_text() for t in a.get_legend().get_texts()])"
# 2 ['Belgium', 'France']
```

The x axis is still categorical because the code passes year strings. A
year-valued x limit is therefore not a substitute for filtering. The current
tick labels stop at 2040 because `index[::20]` starts at 1800, while the data
still includes the final 2050 point. This is expected from the code, not lost
data.

The frame remains a column store while we work: each selected country is a
Series sharing the year index, and the two Series can be filtered with the
same labels before either one reaches matplotlib. Keeping that index intact
prevents an accidental positional mismatch between the two lines. We only
format the display after selecting the observations and converting their
units.


The program exits 0 with no normal output and may emit the Agg warning. Inspect
the figure for title `Population Projections`, labels `Year` and
`Population`, ticks `0M`, `20M`, `40M`, `60M`, and legend entries `Belgium`
and `France`. Flake8 should produce no diagnostics for `ex02`.

## Key take away

We treat suffix-bearing cells as text until we parse their units. We separate
year filtering from tick selection, keep people as the data unit, and format
millions only on the axis. Labels make two line artists identifiable, while
the current `M`-only conversion must not be mistaken for a complete parser.
